الغرض: إغلاق آخر ٣ بنود قبل الطرح الكامل. البندين الأولين لوجستيّان (يحتاجوا شراء/جهاز)، والتالت وقت.

## ١) التوقيع الرقمي (Authenticode) — يحل F2

**ليه؟** النسخة غير الموقّعة بيطلعلها ويندوز تحذير **"Unknown publisher / SmartScreen"** عند أول تشغيل عند العميل — ده بيخوّف صاحب المطبعة ويوحي إن البرنامج فيروس.

**الشهادة — اختار:**
| النوع | التكلفة التقريبية/سنة | SmartScreen |
|---|---|---|
| **OV (Organization Validation)** | أرخص | التحذير بيقلّ ويختفي **بالتدريج** بعد ما عدد تنزيلات كافي يبني سمعة |
| **EV (Extended Validation)** | أغلى + توكن HSM | **بيختفي فورًا** من أول نسخة (سمعة فورية) |

- **ترشيحي:** لو الميزانية تسمح **EV** (أفضل تجربة أول تنزيل). لو لأ، **OV** كافي وبيتحسّن مع الوقت.
- الجهات: Sectigo / DigiCert / GlobalSign. باسم الشركة **Apex Printing Press** (لازم يطابق `MyAppPublisher` في الـ.iss).

**خطوات التوقيع (بعد ما تجيب الشهادة):**
```powershell
# ١. ابنِ النسخة والمُثبِّت الأول (زي المعتاد)
# ٢. وقّع الملف التنفيذي + المُثبِّت:
powershell -ExecutionPolicy Bypass -File installer\sign-release.ps1 `
    -Thumbprint <بصمة-الشهادة> `
    -Files "InstallerOutput\ApexPrintOS-Setup-2.9.0.exe","Publish\ApexPrintOS.exe"
```
السكربت `sign-release.ps1` بيلاقي `signtool` لوحده، يوقّع بـ SHA-256 مع timestamp، **ويتحقّق بعد التوقيع**. لو مفيش شهادة بيقف برسالة واضحة (مفيش توقيع وهمي).

> **مهم:** وقّع الـEXE **قبل** ما تحزمه في المُثبِّت، ووقّع المُثبِّت نفسه بعد ما يتبني. لو بتستخدم Inno Setup، فيه خيار `SignTool=` يوقّع أثناء البناء — أقدر أضبطه لك لو عايز.

**معيار النجاح:** تشغيل المُثبِّت على **ويندوز نضيف** → اسم الناشر **Apex Printing Press** ظاهر، **بدون** تحذير أحمر.

## ٢) اختبار التثبيت النظيف — يغطّي NOT VERIFIED

لازم على **ويندوز نضيف** (VM جديدة أو جهاز ما عليهوش .NET ولا البرنامج قبل كده). الأفضل: Windows Sandbox أو VM سناپشوت.

| # | الخطوة | المتوقع | نجح؟ |
|---|---|---|---|
| ١ | تشغيل المُثبِّت | يفتح، يعرض الرخصة العربية، Accept/Decline شغّالة | [ ] |
| ٢ | التثبيت | يخلّص بدون طلب Admin (per-user)، اختصار على الديسكتوب/ابدأ | [ ] |
| ٣ | أول تشغيل | يفتح بدون خطأ، يطلب التفعيل/التجربة | [ ] |
| ٤ | تفعيل التجربة | ٧ أيام تبدأ، البرنامج يشتغل | [ ] |
| ٥ | إضافة طابعة + طباعة ورقة | تطبع فعلًا (ربط بالبوابة ٢) | [ ] |
| ٦ | غلق وفتح ويندوز | البرنامج والبيانات سليمة، اللغة والمظهر محفوظين | [ ] |
| ٧ | تحديث (فوق نسخة أقدم) | يستبدل النسخة، البيانات والترخيص باقيين، إدخال واحد في Apps&features | [ ] |

**نقطة حرجة:** خطوة ٨ — إلغاء التثبيت **ما يمسحش** سجل الأرقام والترخيص بالغلط (ده بيانات عميل مهمة). تأكد إن ده السلوك المقصود.

## ٣) اختبار الثبات (٢٤ ساعة) — يغطّي Long-Running + Memory

شغّل البرنامج **٢٤ ساعة متواصلة** مع طباعة فعلية أو محاكاة (شغلانات متتالية على "Microsoft Print to PDF" لو مش عايز تستهلك ورق).

**راقب كل ~٦ ساعات وسجّل:**
| الوقت | RAM (MB) | Handles | Threads | حجم DB (MB) | Temp files | ملاحظة |
|---|---|---|---|---|---|---|
| البداية | | | | | | |
| ٦ س | | | | | | |
| ١٢ س | | | | | | |
| ٢٤ س | | | | | | |

**أوامر المراقبة (PowerShell):**
```powershell
# لقطة سريعة كل شوية:
Get-Process Apex.UI | Select-Object `
  @{n='RAM_MB';e={[math]::Round($_.WorkingSet64/1MB)}}, HandleCount, Threads.Count
# حجم قاعدة البيانات وملفات temp:
Get-ChildItem "$env:APPDATA\Apex" -Recurse -File | Measure-Object Length -Sum
Get-ChildItem $env:TEMP -Filter "*apex*" -ErrorAction SilentlyContinue | Measure-Object
```

**معيار النجاح:**
- الـRAM **ما تزيدش باستمرار** (تصعد وتنزل مع الشغل، مش خط صاعد ثابت = تسريب).
- الـHandles/Threads مستقرة (مش بتتراكم).
- ملفات الـtemp بتتنضّف بعد كل شغلانة (مش بتتراكم).
- الأداء آخر الـ٢٤ ساعة زي أوله (مفيش تباطؤ تدريجي).

> ملاحظة من الـAudit: فيه اختبار آلي `FullJob_LargeJob_StreamingMemoryEfficient` بيقيس نمو الذاكرة، بس حدّه صارم ومتقلّب — الاختبار الفعلي ده (٢٤ ساعة على جهاز) هو الحكم الحقيقي على وجود تسريب من عدمه.
